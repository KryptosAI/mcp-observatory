01

Start here

Run your first scan

Open a terminal in your project. Try the bundled example first, then test your own startup command or target configuration. scan discovers configured servers; scan deep also invokes eligible tools. Only scan servers you are authorized to run.

Commands for this workflow

Requires Node.js 20+. Replace example paths and commands with your own. Commands ending in --help explain options without starting a server.

npx -y @kryptosai/mcp-observatory@latest demo --example
npx -y @kryptosai/mcp-observatory@latest test --target target.json
npx -y @kryptosai/mcp-observatory@latest scan
npx -y @kryptosai/mcp-observatory@latest scan deep
npx -y @kryptosai/mcp-observatory@latest score --help
NEXT STEP

Read the failing check, its evidence and suggested fix. A successful connection is not proof that every tool works.

Understand and share the evidence

The gate tells you whether configured checks passed. A partial or unsupported check leaves a coverage gap. Scores summarize evidence; inspect the checks before making a release decision. Save JSON for automation, HTML for people, SARIF for code scanning, and Markdown or JUnit for CI.

npx -y @kryptosai/mcp-observatory@latest receipt --help
NEXT STEP

Keep the original receipt. Use enterprise-report for a local report across saved runs; it does not require a paid account.

03

Free local tools

Catch changes before a release

Save a passing baseline, then compare a later run. diff explains regressions and schema changes. Permission-change gates can block witnessed widening or queue unsupported changes for review. A lock file snapshots the advertised contract.

Commands for this workflow

Requires Node.js 20+. Replace example paths and commands with your own. Commands ending in --help explain options without starting a server.

npx -y @kryptosai/mcp-observatory@latest diff base.json head.json --format html --output diff.html
npx -y @kryptosai/mcp-observatory@latest diff base.json head.json --fail-on-permission-delta review
npx -y @kryptosai/mcp-observatory@latest lock --help
npx -y @kryptosai/mcp-observatory@latest lock verify --help
NEXT STEP

Fix the changed contract or explicitly review it before updating your baseline. Unsupported schemas are review leads, not a proven permission expansion.

04

Free · local and opt-in

Investigate “I asked X, got Y”

Instrument your server with observeTool and UsageStore. Correlate tool calls with an explicitly supplied request context. Server-side evidence includes calls, allowed arguments, errors and latency. The original conversation stays invisible unless the user deliberately shares it; a model summary is labeled as a proxy.

Commands for this workflow

Requires Node.js 20+. Replace example paths and commands with your own. Commands ending in --help explain options without starting a server.

npx -y @kryptosai/mcp-observatory@latest usage review --dir .mcp-observatory/usage
npx -y @kryptosai/mcp-observatory@latest usage feedback-template
npx -y @kryptosai/mcp-observatory@latest usage analyze --dir .mcp-observatory/usage
npx -y @kryptosai/mcp-observatory@latest usage export --help
NEXT STEP

Open a request and flag “This wasn’t what I wanted” in one step. Review linked calls and group requests by intent. Unknown outcomes stay separate from confirmed failures. Export a regression case, then define its expected-outcome assertion.

05

Free · advisory

Review source, packages and server combinations

source-audit inspects bounded JS/TS patterns without executing the project. package-check reviews package-name similarity without launching the supplied command. toxic-flow reviews saved tool inventories across servers. These are review leads; incomplete coverage exits 2.

Commands for this workflow

Requires Node.js 20+. Replace example paths and commands with your own. Commands ending in --help explain options without starting a server.

npx -y @kryptosai/mcp-observatory@latest source-audit ./src --format json
npx -y @kryptosai/mcp-observatory@latest package-check --format json -- npx -y @modelcontextprotocol/server-filesystem .
npx -y @kryptosai/mcp-observatory@latest toxic-flow base.json head.json --format json
npx -y @kryptosai/mcp-observatory@latest skill-scan --help
NEXT STEP

Read the coverage limits and verify a finding in context. For toxic-flow, use snapshots from distinct servers; two versions of the same target are not a cross-server inventory.

Local CI is free

Keep checks running in CI

Generate a GitHub workflow for a known server command. --sarif adds GitHub Code Scanning output. --doctor checks the adoption kit. Local CI runs without a hosted plan; hosted CI ingestion is a Pro feature.

Commands for this workflow

Requires Node.js 20+. Replace example paths and commands with your own. Commands ending in --help explain options without starting a server.

npx -y @kryptosai/mcp-observatory@latest setup-ci --all --command "node server.mjs" --sarif
npx -y @kryptosai/mcp-observatory@latest setup-ci --doctor
npx -y @kryptosai/mcp-observatory@latest init-ci --help
npx -y @kryptosai/mcp-observatory@latest ci-report --help
NEXT STEP

Inspect the generated workflow, supply required server credentials as repository secrets, commit it and review the first CI result. Never paste secrets into screenshots or target files.

07

Free snapshot · optional Pro

Save a snapshot in your portal

Run cloud upload from the folder containing your receipt. Follow the terminal’s GitHub verification link, approve the matching code, and open the dashboard. Free keeps one target’s latest snapshot for seven days with 10 uploads per month. Individual Pro adds history, hosted HTTP scans, CI ingestion and artifact downloads; check current pricing before upgrading.

Commands for this workflow

Requires Node.js 20+. Replace example paths and commands with your own. Commands ending in --help explain options without starting a server.

npx -y @kryptosai/mcp-observatory@latest cloud upload
npx -y @kryptosai/mcp-observatory@latest cloud --help
NEXT STEP

In the portal, inspect Latest results, open a report, and check your remaining quota. Pro history highlights regressions. A hosted HTTP scan needs a reachable authorized endpoint; upload local receipts for local-process servers.

Record, replay and monitor

Record a server session as a cassette, replay it offline, and verify a live server against it. watch checks repeatedly and history shows local score trends. Recordings can contain server responses: use sample data first and inspect them before sharing.

11

Your storage, your choice

Control what gets collected

Usage learning and product telemetry are separate. Usage capture defaults to minimal call metadata; allow argument fields explicitly and collect conversation context only with consent. Choose the UsageStore directory and retention. Keep local data on your own disk or encrypted volume; hosted uploads use the hosted service’s storage and retention.

Commands for this workflow

Requires Node.js 20+. Replace example paths and commands with your own. Commands ending in --help explain options without starting a server.

npx -y @kryptosai/mcp-observatory@latest usage prune --help
npx -y @kryptosai/mcp-observatory@latest telemetry status
npx -y @kryptosai/mcp-observatory@latest telemetry preview
npx -y @kryptosai/mcp-observatory@latest telemetry disable
NEXT STEP

Review redacted evidence before sharing it. You can stop after a local scan. A telemetry opt-out does not delete hosted receipts or local usage records.
